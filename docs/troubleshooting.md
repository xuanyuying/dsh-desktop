# 故障排查

排查任何问题前，先做两件事：

1. 菜单「工具 → 内置日志查看器」（`Ctrl+Shift+L`），看最近的 `[error]` / `[warning]`
2. 命令行运行体检：

```powershell
node scripts\doctor.js
```

它会输出环境、服务、认证、余额、代理、端口的当前状态。

## 启动不了 / 窗口空白

| 现象 | 原因与处理 |
| --- | --- |
| 窗口一直停在"正在启动" | 服务没起来。看日志里的 `service launch error`；多半是 `dsh` 未安装或 Node 不在 PATH |
| 空白页 | 历史原因是 dsh 0.1.5+ 的认证：裸访问 3080 返回 401。应用会捕获启动输出里的 `?token=` URL 并加载它；若日志里出现 `no token needed` 而页面仍空白，按下一行处理 |
| 界面显示旧版本 | `app.asar` 没换成功。确认 `resources\app.asar` 的大小/日期，或直接重新安装 |

**终极兜底**：用安全模式启动，跳过托盘等窗口管理功能，只保留「起服务 + 载界面」：

```powershell
$env:DSH_DESKTOP_SAFE=1
& 'D:\...\DSH Desktop\DSH Desktop.exe'
```

## 端口冲突

应用默认用 **3080**。若该端口已被别的服务占用：

- **应用会退让到下一个空闲端口**，并在日志里写 `端口 3080 被其它服务占用，自动改用 3081（不会结束任何进程）`
- 它**不会**杀掉占用端口的进程 —— 那可能是你正在用的另一个 harness

如果你确认要清理占用者，菜单「工具 → 结束占用端口的 dsh 服务…」：它只结束**命令行确认为 `dsh web`** 的进程，并且会先弹窗确认。

想换固定端口：设环境变量 `DSH_DESKTOP_PORT`。

## 高峰时段发不出消息

这是**预期行为**——高峰时段零 token 保护生效了。

- 看菜单栏标签是否显示 `高峰，...`，以及菜单里「守卫」那行是否为 `运行中`
- 确实需要现在工作：菜单 →「临时放行至本时段结束」
- 想彻底关掉保护：菜单 → 取消勾选「高峰时段零 token 消耗」

## 「守卫：⚠ 未生效」

说明当前 harness 进程里没有加载 `peak-guard.mjs`，此时高峰**不会**被拦截（会正常消耗 token）。

常见原因：复用了别处启动的、没有带 `--patch` 的服务。处理：

1. 菜单 →「重启服务以启用保护」（会用正确的参数重启 harness）
2. 若仍无效，检查 `<安装目录>\resources\peak-guard.mjs` 是否存在

## 余额显示「不可用」

1. 菜单「文件 → 设置…」确认已配置 Key（界面会显示来源与是否加密）
2. 环境变量 `DEEPSEEK_API_KEY` 优先级最高，若设了但值是错的，会一直失败
3. 有代理时确认 `HTTPS_PROXY` / `NO_PROXY` 正确；应用会把它们透传给服务

## 窗口底部被任务栏裁掉

已经修过：窗口会按显示器工作区收敛。若仍异常，删掉 `~/.dsh-desktop/ui-state.json` 让它重新计算。

## 检查更新报「无法访问 GitHub Releases」

一般是网络/代理问题。也可直接到 Releases 页面手动下载安装包覆盖安装。

## 多开

应用有单实例锁：重复启动只会聚焦已有窗口，不会起第二份服务。

## 报告问题时请附上

- `~/.dsh-desktop/desktop.log`（可先用内置查看器清空无关内容）
- `node scripts\doctor.js` 的输出
- `dsh --version` 与应用的「关于」里显示的版本
